# LLM Lab 第二阶段升级计划

## 目标

在不打乱现有一级导航的前提下，把平台从当前偏 ESG 提取的单一路径，升级成可承载多任务、多技术路线、多线上环境的通用实验平台。

本阶段一级入口保持不变：

- 测试集工作台
- 线上验证工作台
- 数据预处理工作台
- 说明文档

## 核心抽象

后续平台统一围绕 4 个核心对象扩展：

### 1. 任务类型

定义任务输入输出契约与验收口径。

第一阶段正式支持：

- 结构化抽取

后续可扩展：

- 分类 / 判定
- 改写 / 整理
- JSON 生成

### 2. 技术路线

定义任务怎么跑，不和模型预设混在一起。

首批路线：

- 多模态直读
- OCR 转文本
- OCR + RAG
- 纯文本 / Excel

### 3. 模型预设

只负责：

- 供应商
- 接口地址
- 模型名
- API Key 来源
- 高级请求参数
- 能力标签

不负责：

- 是否 OCR
- 是否走 RAG
- 页码策略
- chunk 策略

### 4. 线上环境

定义真实运行目标。

一个环境至少包含：

- 名称
- 任务类型
- 技术路线
- 绑定模型槽位
- 运行参数
- 输出结构
- 验收方案

## 工作台改造方向

## 测试集工作台

保留 3 个子页：

- Prompt 快速迭代
- 模型结果验收
- Prompt 自动优化

改造原则：

- 页面壳保持稳定
- 顶部增加任务类型与技术路线上下文
- 子页内容按技术路线变化

例如：

- 多模态直读显示 PDF、页码与视觉模型
- 纯文本 / Excel 显示文本或表格上传，不显示页码
- OCR + RAG 增加 OCR 与检索参数

## 模型结果验收

改成：

- 通用底座指标
- 任务类型专属指标包
- 页面上只勾选展示哪些指标

结构化抽取默认指标：

- 精确率
- 召回率
- F1
- 严格通过率
- 宽松通过率
- 幻觉率
- 漏提率
- 重复率
- 页码命中率
- 单位 / 年份正确率

## 线上验证工作台

改成“环境驱动”模式：

- 先选线上环境
- 再进入该环境的运行界面

环境第一阶段先做本地持久化：

- 新增
- 编辑
- 复制
- 禁用
- 删除
- JSON 导入导出

## 当前实施顺序建议

### 第一阶段：低风险输入扩展

先把 `Prompt 快速迭代` 扩成支持多输入源：

- PDF
- Excel / CSV
- 文本文件

只扩 `结构化抽取`，不同时做 OCR / RAG / 环境管理。

### 第二阶段：技术路线显式化

在测试集工作台里把输入源抽象升级成技术路线：

- 多模态直读
- OCR 转文本
- OCR + RAG
- 纯文本 / Excel

### 第三阶段：验收体系通用化

把当前 ESG 验收逻辑沉淀成 `结构化抽取` 的标准模板，再扩其他任务类型。

### 第四阶段：线上环境多实例化

把现有线上验证工作台改成环境列表 + 环境运行壳。

## 当前实现边界

本文件仅作为后续升级的主线计划，不要求一次性做完。

最近一刀优先级最高的是：

- Prompt 快速迭代支持 Excel / CSV / 文本文件上传

原因：

- 改动面最小
- 能先验证“多输入介质”是否顺手
- 不会提前把 OCR / RAG / 环境系统拉进来
